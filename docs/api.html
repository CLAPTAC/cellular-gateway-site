API reference

Authentication, messages, calls, commands, devices, groups, users and API keys, with request and response examples.

All endpoints live under /api/v1 and speak JSON. In development, /docs serves the full interactive OpenAPI schema; it is disabled in production.

Authentication#

MethodHowAccepted on
API keyX-API-Key: cgk_.... Created by an administrator in the dashboard and shown once/messages, /calls and /commands endpoints only
Bearer tokenAuthorization: Bearer <jwt> from POST /auth/loginAll user endpoints
Session cookiecg_session, httpOnly and SameSite=Strict (Secure in production), set by the same login call. Used by the dashboard. Writes also require an allowed OriginAll user endpoints

An API key acts with the permissions of the administrator who created it. Revoke keys individually from the dashboard or with DELETE /api-keys/{id}.

POST/api/v1/auth/login
Request
{ "email": "admin@example.com", "password": "..." }

Returns {"access_token": "...", "token_type": "bearer"} and sets the session cookie. Failed attempts are rate limited per IP and per email.

Messages#

POST/api/v1/messages

Creates an outbound SMS. Requires the operator or admin role.

FieldTypeDescription
tostringDestination number. Required
messagestring1 to 1600 characters. Required
devicestringDevice key or UUID. Targets one phone
groupstringGroup slug or UUID. A phone is chosen by strategy
strategystringhealthiest (default), round_robin, highest_battery, least_load
queuebooleantrue holds the message until a phone is online. Default false
failoverbooleanDefault true. Retries a failed send on another phone in the same group, up to 3 attempts. No effect without group
curl
curl -X POST https://gateway.example.com/api/v1/messages \
  -H "X-API-Key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"group": "primary", "to": "+15551234567", "message": "Your code is 482913"}'
Python
import os, requests

r = requests.post(
    "https://gateway.example.com/api/v1/messages",
    headers={"X-API-Key": os.environ["GATEWAY_API_KEY"]},
    json={"group": "primary", "to": "+15551234567", "message": "Your code is 482913"},
    timeout=15,
)
r.raise_for_status()
message = r.json()
print(message["id"], message["status"])
Node

If neither device nor group is given, any enabled device is eligible. If the chosen device is offline the call fails with 409, unless queue is true or a group is used (groups queue automatically). Message statuses: QUEUED, SENDING, SENT, DELIVERED, FAILED, RECEIVED.

GET/api/v1/messages

Lists messages, newest first. Query parameters: device_id (UUID) and limit (1 to 200, default 50). GET /api/v1/messages/{id} returns one message. Inbound SMS appear here with direction INBOUND and status RECEIVED.

Calls#

POST/api/v1/calls

Starts an outbound call. Fields: to (required), device, group, strategy, queue. Calls have no failover. Requires the operator or admin role.

Response, 201 Created (queued)

  "to_number": "+15551234567",
  "started_at": null,
  "answered_at": null,
  "ended_at": null,

POST/api/v1/calls/{id}/end

Ends an active call (Android 9 or newer). GET /api/v1/calls and GET /api/v1/calls/{id} read history (same device_id and limit parameters). Call statuses: QUEUED, DIALING, RINGING, ACTIVE, HOLDING, ENDED, FAILED, CANCELLED.

Commands#

POST/api/v1/commands

Sends a raw command to one device. Body: device_id or device_key, type (default PING), payload, optional request_id. Requires the operator or admin role.

Accepted types: SMS_SEND, SMS_CANCEL, CALL_START, CALL_END, DEVICE_STATUS, DEVICE_COMMAND, PING. The current Android app executes SMS_SEND, CALL_START, CALL_END, PING and DEVICE_STATUS, and reports the others as unsupported.

Command statuses: PENDING, QUEUED, SENT, ACKNOWLEDGED, COMPLETED, FAILED, CANCELLED. Read them with GET /commands, GET /commands/{id} and GET /commands/by-request/{request_id}.

Groups#

POST/api/v1/groups
Request (admin)
{
  "name": "Primary",
  "slug": "primary",
  "routing_strategy": "healthiest",
  "device_ids": ["<device-uuid>"]
}

slug is 1 to 64 characters of lowercase letters, digits, - and _, starting with a letter or digit. PATCH /groups/{id} accepts name, description, routing_strategy, is_active and device_ids (which replaces the member list). GET /groups/{id}/preview and GET /groups/route-preview?group=&strategy= show which device would be chosen and its score, without sending anything. See Multi-device routing.

Users and API keys#

EndpointPurpose
POST /usersCreate a portal user: email, password (8 to 128 characters), full_name, role (default operator)
GET /users, PATCH /users/{id}List users; change role, is_active, full_name or password
POST /api-keysCreate a key with a name. The full key is returned once
GET /api-keys, DELETE /api-keys/{id}List your keys; revoke one

All of these require the admin role.

Dashboard data and health#

  • GET /dashboard/stats: device and command counts
  • GET /dashboard/analytics?days=7 (1 to 90): message, call and command totals, volume by day and top devices
  • GET /dashboard/recent-devices, GET /dashboard/recent-commands
  • GET /health (no authentication): {"status":"ok","service":"Cellular Gateway"}
