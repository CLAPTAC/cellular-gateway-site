Security

How the gateway protects credentials, browser sessions, webhooks and the network edge, and what you still need to do.

What the gateway enforces#

AreaBehaviour
StartupWith ENVIRONMENT=production the server refuses to start on default or weak secrets, SQLite, or localhost CORS
TransportTLS terminates at Caddy or your reverse proxy. Release builds of the Android app block plain HTTP
Browser sessionsAn httpOnly cookie, so page scripts cannot read the token, plus SameSite=Strict and an Origin check on cookie-authenticated writes
Secrets at restPasswords, device tokens and API keys are stored as bcrypt hashes. Webhook secrets are stored in plain form because they are needed to sign deliveries
Device credentialsSent in X-Device-Key and X-Device-Token headers so they stay out of proxy logs. Tokens can be rotated at any time
Rate limitingFailed logins (per IP and per email), device registration and device WebSocket authentication. State is in memory and resets on restart
Webhook targetshttps in production, public addresses only, checked when saved and again at delivery, with the connection pinned to the validated IP and redirects disabled
Forwarded headersX-Forwarded-For is trusted only from loopback and private addresses
ContainersThe API and dashboard images run as a non-root user. In the production compose files PostgreSQL is not published to the host
API docs/docs, /redoc and /openapi.json are disabled in production

Roles#

RoleCan do
viewerRead devices, groups, messages, calls, commands, dashboard and analytics
operatorEverything a viewer can, plus send SMS, start or end calls and create commands
adminEverything, including devices, groups, webhooks, users and API keys

API keys act with the permissions of the administrator who created them and are accepted only on the messages, calls and commands endpoints. Create one key per integration so each can be revoked on its own.

Your checklist#

  • Use long random values for SECRET_KEY and POSTGRES_PASSWORD, and a strong administrator password.
  • Expose only ports 80 and 443. Keep SSH restricted, and keep the host patched.
  • Verify webhook signatures on your receiver and deduplicate on the delivery id.
  • Rotate a device token if a phone or QR code is lost, and disable devices you no longer use.
  • Back up the database and store backups off the server.
  • Remember that SMS content passes through the gateway and is stored in its database. Treat the database as sensitive.
Reporting vulnerabilities

Please report security issues privately to the maintainers rather than opening a public issue.
