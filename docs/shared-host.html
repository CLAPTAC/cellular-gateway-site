Deploy

Behind a reverse proxy

Run the gateway on a host that already has nginx, Apache, Traefik or Caddy. The stack binds to loopback and your proxy handles TLS.

Use docker-compose.shared.yml when the host already serves other sites and ports 80 and 443 are taken. It starts PostgreSQL, the API and the dashboard, without Caddy. The API listens on 127.0.0.1:18000 and the dashboard on 127.0.0.1:13000 (change them with GATEWAY_API_PORT and GATEWAY_DASHBOARD_PORT). PostgreSQL is not published.

Start the stack#

bash
cp .env.production.example .env.production   # GATEWAY_DOMAIN = your public hostname
docker compose --env-file .env.production -f docker-compose.shared.yml up -d --build
curl -s http://127.0.0.1:18000/health

Routing rules#

Add a host for GATEWAY_DOMAIN in your proxy with these rules, whichever proxy you use:

PathUpstream
/api/*, /health127.0.0.1:18000
/ws/*127.0.0.1:18000, with WebSocket upgrade
everything else127.0.0.1:13000

The proxy must serve HTTPS (release builds of the Android app refuse http://) and send X-Forwarded-For and X-Forwarded-Proto. Phones send a heartbeat every 10 seconds, so a read timeout of a few minutes is plenty.

Keep the ports on loopback

The API only trusts X-Forwarded-For from loopback and private addresses (FORWARDED_ALLOW_IPS), so a public connection cannot fake its IP to dodge rate limits. There is still no reason to expose ports 18000 or 13000. If your proxy connects from a public or unusual address, set FORWARDED_ALLOW_IPS to it.

Proxy configuration#

nginx
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
    listen 443 ssl http2;
    server_name gateway.example.com;
    ssl_certificate     /etc/letsencrypt/live/gateway.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/gateway.example.com/privkey.pem;

    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;

    location /ws/ {
        proxy_pass http://127.0.0.1:18000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
    location ~ ^/(api/|health$) { proxy_pass http://127.0.0.1:18000; }
    location / { proxy_pass http://127.0.0.1:13000; }
}
Caddy
gateway.example.com {
	@api path /api/* /ws/* /health
	reverse_proxy @api 127.0.0.1:18000
	reverse_proxy 127.0.0.1:13000
}
Apache
# Needs mod_proxy, mod_proxy_http, mod_proxy_wstunnel, mod_headers, mod_rewrite
<VirtualHost *:443>
    ServerName gateway.example.com
    # ... SSLEngine and certificate directives ...
    RequestHeader set X-Forwarded-Proto "https"
    ProxyPreserveHost On
    ProxyTimeout 300
    RewriteEngine On
    RewriteCond %{HTTP:Upgrade} =websocket [NC]
    RewriteRule ^/ws/(.*) ws://127.0.0.1:18000/ws/$1 [P,L]
    ProxyPass        /api/   http://127.0.0.1:18000/api/
    ProxyPassReverse /api/   http://127.0.0.1:18000/api/
    ProxyPass        /health http://127.0.0.1:18000/health
    ProxyPass        /       http://127.0.0.1:13000/
    ProxyPassReverse /       http://127.0.0.1:13000/
</VirtualHost>
Traefik
# Traefik runs in Docker and cannot reach 127.0.0.1 on the host.
# Attach the services to Traefik's network instead of using the loopback ports.
services:
  server:
    networks: [default, traefik]
    labels:
      - traefik.enable=true
      - traefik.http.routers.gw-api.rule=Host(`gateway.example.com`) && (PathPrefix(`/api`) || PathPrefix(`/ws`) || Path(`/health`))
      - traefik.http.routers.gw-api.tls.certresolver=letsencrypt
      - traefik.http.services.gw-api.loadbalancer.server.port=8000
  dashboard:
    networks: [default, traefik]
    labels:
      - traefik.enable=true
      - traefik.http.routers.gw-ui.rule=Host(`gateway.example.com`)
      - traefik.http.routers.gw-ui.priority=1
      - traefik.http.routers.gw-ui.tls.certresolver=letsencrypt
      - traefik.http.services.gw-ui.loadbalancer.server.port=3000
networks:
  traefik: { external: true }

Traefik handles WebSocket upgrades automatically. With Traefik, remove the ports: entries and make sure only Traefik can reach the API container.

Check it works#

  • curl https://gateway.example.com/health returns {"status":"ok","service":"Cellular Gateway"}.
  • Sign in at https://gateway.example.com/.
  • Connect a device and confirm it stays ONLINE for more than a minute. If it flips between ONLINE and OFFLINE, check for a proxy timeout under about 30 seconds, then phone battery optimization and network stability.
