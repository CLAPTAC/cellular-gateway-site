Webhooks

Receive signed events for inbound SMS, delivery results, call state and device status, with retries and a delivery history.

Create an endpoint#

Administrators create endpoints in the dashboard (Webhooks) or with the API.

POST/api/v1/webhooks
Request
{
  "name": "crm",
  "url": "https://example.org/hooks/gateway",
  "events": ["SMS_RECEIVED", "SMS_FAILED"]
}

events defaults to all event types, and "*" is accepted. The response contains the signing secret (whsec_...) exactly once; rotate it with POST /webhooks/{id}/rotate-secret. List endpoints with GET /webhooks, update or deactivate them with PATCH /webhooks/{id}, and read recent attempts with GET /webhooks/{id}/deliveries (latest 50).

Events#

EventEmitted whendata fields
SMS_RECEIVEDA phone receives an SMSfrom, body (truncated to 200 characters), message_id
SMS_SENTAn outbound SMS command completesrequest_id, result
SMS_FAILEDAn outbound SMS command failsrequest_id, error
CALL_STATEA call changes statestate, status, call_id, number
DEVICE_ONLINE, DEVICE_OFFLINEA phone connects or disconnectsconnection_id
COMMAND_COMPLETED, COMMAND_FAILEDAny command finishesrequest_id, command_type, result or error

Every data object also carries device_id and a human-readable message. For inbound SMS the body in the webhook is cut at 200 characters; fetch the full text with GET /api/v1/messages/{message_id}.

Delivery format#

POST to your URL
{
  "id": "<delivery uuid>",
  "type": "SMS_RECEIVED",
  "created_at": "2026-01-01T12:00:00+00:00",
  "data": {
    "from": "+15551234567",
    "body": "Hello",
    "message_id": "...",
    "device_id": "...",
    "message": "Inbound SMS from +15551234567"
  }
}
HeaderValue
Content-Typeapplication/json
X-CG-EventThe event type
X-CG-DeliveryDelivery id, identical to id in the body
X-CG-Signaturesha256=<hex>, the HMAC-SHA256 of the raw body

Verify the signature#

Compute the HMAC-SHA256 of the raw request body with the endpoint secret and compare it in constant time. Do not re-serialize the JSON before checking.

Python
import hashlib, hmac

def is_valid(secret: str, raw_body: bytes, header: str) -> bool:
    expected = "sha256=" + hmac.new(secret.encode(), raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)
Node
import crypto from "node:crypto";

export function isValid(secret, rawBody, header) {
  const expected = "sha256=" + crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  const a = Buffer.from(expected);
  const b = Buffer.from(header ?? "");
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

Delivery rules#

  • A 2xx response within 10 seconds counts as success. Anything else is retried.
  • There are up to 5 attempts in total, spaced 30 seconds, 2 minutes, 10 minutes and 30 minutes apart (about 42 minutes overall). After that the delivery is marked FAILED.
  • The id stays the same across retries. Deduplicate on it, because a delivery can arrive more than once. Order is not guaranteed.
  • URLs must use https in production and must resolve to public addresses. The check runs when you save the endpoint and again at every delivery, and the connection is pinned to the validated IP address. Redirects are not followed.
What SMS_SENT means

SMS_SENT means the phone's radio accepted the message for sending. It is not a delivery receipt from the recipient's carrier.
