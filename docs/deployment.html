Deploy

Production deployment

Deploy the gateway on a Linux host with Docker Compose, automatic HTTPS through Caddy, PostgreSQL and Alembic migrations.

This guide uses docker-compose.prod.yml: Caddy, the API, the dashboard and PostgreSQL on one host. Caddy is the only service that publishes ports (80 and 443). If the host already runs a reverse proxy, use Behind a reverse proxy instead.

Prerequisites#

  • A Linux host with Docker and Docker Compose, with ports 22, 80 and 443 reachable
  • A DNS record (for example gateway.example.com) pointing at the host. Caddy needs it to obtain a certificate
  • About 2 vCPU and 2 GB RAM is a reasonable starting point for a pilot (an estimate, not a benchmark). Building the dashboard image needs the most memory, so add swap on small hosts

1. Configure#

bash
git clone https://github.com/CLAPTAC/cellular-gateway.git
cd cellular-gateway
cp .env.production.example .env.production
openssl rand -hex 32   # run twice: SECRET_KEY and POSTGRES_PASSWORD

Edit .env.production and set:

VariableValue
GATEWAY_DOMAINThe public hostname, for example gateway.example.com
POSTGRES_PASSWORDA random password
SECRET_KEYA random string of at least 32 characters (JWT signing key)
ADMIN_EMAIL, ADMIN_PASSWORDYour administrator login; password of at least 12 characters
The server refuses weak configuration

With ENVIRONMENT=production (set by the compose file) the server will not start if SECRET_KEY is a default or shorter than 32 characters, the admin password is a default or shorter than 12 characters, the admin email is admin@example.com, the database is SQLite, or CORS lists localhost. The error message lists every problem.

2. Start#

bash
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps

On start the server container applies database migrations (alembic upgrade head) and then runs a single uvicorn worker.

3. Verify#

bash
curl https://gateway.example.com/health
# {"status":"ok","service":"Cellular Gateway"}

Open https://gateway.example.com/ and sign in with your administrator account.

WhatAddress
Dashboardhttps://<domain>/
APIhttps://<domain>/api/v1
Device WebSocketwss://<domain>/ws/devices
Healthhttps://<domain>/health

Interactive API docs (/docs) are disabled in production.

4. Connect phones#

Install a release build of the Android app and use https://<domain> as the server URL, ideally by scanning the device QR code from the dashboard. Release builds block plain HTTP. See Android app.

Run exactly one server instance#

Device WebSocket sessions and the background workers (offline detection, command queue, webhook delivery) live inside the server process. Do not run more than one replica or use --workers greater than 1. Multi-instance coordination is not implemented.

Updates, backups and logs#

Update
git pull
docker compose --env-file .env.production -f docker-compose.prod.yml up -d --build
Back up the database
docker compose -f docker-compose.prod.yml exec postgres \
  pg_dump -U gateway cellular_gateway > backup.sql
Logs
docker compose -f docker-compose.prod.yml logs -f server

Keep backups off the server. Phones reconnect automatically after an update. If you adopt a database that was created by an older development build, run alembic stamp head once inside the server container.
