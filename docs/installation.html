Quickstart

Run the gateway locally with SQLite, open the dashboard, and test the full device path with the simulator. No phone required.

Requirements#

  • Python 3.12 and Node.js 22
  • Optional: Docker and Docker Compose, Android Studio (JDK 17) for the phone app

1. Start the server#

The server uses SQLite by default, so no configuration is needed for local development.

bash
cd server
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

Settings come from environment variables or server/.env. The .env in the repository root is only used by Docker Compose.

2. Start the dashboard#

bash
cd dashboard
npm install
NEXT_PUBLIC_API_URL=http://localhost:8000 npm run dev
ServiceURL
Dashboardhttp://localhost:3000
API documentation (development only)http://localhost:8000/docs
Health checkhttp://localhost:8000/health

Sign in with the development administrator admin@example.com / changeme. These defaults are rejected when ENVIRONMENT=production.

With Docker Compose instead#

bash
cp .env.example .env
docker compose up --build

This runs PostgreSQL, the server and the dashboard with live reload. All ports bind to 127.0.0.1.

3. Connect a simulated phone#

  1. Create a device. In the dashboard open Devices and add one. Copy the one-time device_key and device_token.
  2. Run the simulator.
    bash
    cd server && source .venv/bin/activate
pip install -r ../examples/requirements.txt
python ../examples/device_simulator.py \
  --device-key 'dev_...' --device-token 'dvt_...'
# options: --base-url (default http://localhost:8000)
#          --heartbeat-interval (default 10 seconds)
  3. Send a PING. Open the device page and send a PING. The command should move to COMPLETED and the device should show ONLINE.

4. Use a real phone#

Build and install the Android app (see Android app), then scan the device's QR code. For the emulator, use http://10.0.2.2:8000 as the server URL. This works in debug builds only; release builds require HTTPS.

Run the tests#

bash
cd server
pip install -r requirements-dev.txt
pytest

The suite covers production safety checks, login rate limiting, cookie sessions and origin checks, webhook URL protection, device WebSocket authentication, group routing and the examples from these docs.
