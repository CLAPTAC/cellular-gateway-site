Devices

QR provisioning

Connect a phone by scanning a QR code instead of typing a server URL and long credentials.

When you create a device, or rotate its token, the dashboard shows a QR code. Scanning it in the Android app fills in the server URL and credentials and connects automatically.

Payload#

json
{
  "v": 1,
  "server_url": "https://gateway.example.com",
  "device_key": "dev_...",
  "device_token": "dvt_..."
}

The QR code contains the device token, so treat it like a password. It is shown once, at creation or rotation.

Flow#

  1. Create the device. Dashboard, then Devices, then add a device.
  2. Set the server URL for the phone. It must be reachable from the phone. For local testing use your computer's LAN address, not localhost. In production use your public https:// URL.
  3. Scan. In the phone app choose Scan QR. It fills the fields and connects.

Show the QR code again#

Open the device and choose Show QR again. This issues a new token, so the previous token stops working and the phone must scan again.

Why not type credentials

Device tokens are long random strings. Scanning avoids typing mistakes and keeps the token off the clipboard.
